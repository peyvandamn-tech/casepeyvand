# سناریوی کامل تست دستی — پیوند امن (بعد از مهاجرت Supabase)

این سناریو کل مسیر واقعی رو از صفر تا انتها پوشش می‌ده. چون این حجم تغییر async
بدون مرورگر واقعی قابل تست خودکار نبود، این چک‌لیست جایگزین اون تست دستیه.
هر بخش رو به ترتیب انجام بده — بخش‌های بعدی به نتیجه‌ی درست قبلی وابسته‌ن.

## پیش‌نیاز راه‌اندازی (یک‌بار)

- [ ] اسکیمای `supabase_schema.sql` روی پروژه‌ی Supabase واقعی اجرا شده
- [ ] Edge Function `send-sms-hook` دیپلوی و در Auth Hooks فعال شده
- [ ] Secretهای `MELIPAYAMAK_*` و `SEND_SMS_HOOK_SECRET` تنظیم شده‌اند
- [ ] `SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY` روی Worker/Server تنظیم شده (نه در بیلد فرانت‌اند!)
- [ ] یک حساب کارشناس (EXPERT) با کوئری زیر ساخته شده (چون ثبت‌نام تلفنی همیشه CLIENT می‌سازه):
  ```sql
  -- بعد از این‌که این شماره یک‌بار با OTP وارد شد و ردیف users خودکار ساخته شد:
  update users set role = 'EXPERT', full_name = 'مهناز خوینی' where phone = '+98912xxxxxxx';
  ```
- [ ] دو شماره موبایل واقعی (یا Test Phone Number از داشبورد Supabase) برای دو مراجع آماده است

---

## بخش ۱ — ثبت‌نام و تشکیل پرونده (مراجع «سارا»، خانم)

1. صفحه‌ی فرود رو باز کن — **بررسی کن**: هیچ منوی «کاربران دمو» یا سوییچ نقشی دیده نمی‌شه.
2. «شروع و تشکیل پرونده» → شماره را وارد کن → کد OTP باید واقعاً پیامک بشه (نه کد ثابت).
3. کد را وارد کن → چون کاربر جدیده، فرم «تکمیل ثبت‌نام» باز می‌شه → نام و جنسیت «خانم» را وارد کن.
4. **بررسی کن**: یک پرونده با وضعیت `CONSENT_PENDING` خودکار ساخته شده.

## بخش ۲ — رضایت‌نامه‌ها

5. مودال رضایت‌نامه را باز کن و هر ۳ رضایت‌نامه‌ی الزامی را بپذیر.
6. **بررسی کن**: بعد از پذیرش سومی، وضعیت پرونده خودکار به `PAYMENT_PENDING` تغییر کرد (بدون این‌که کلاینت مستقیم UPDATE بزنه — این کار تریگر دیتابیسه).

## بخش ۳ — پرداخت (مسیر کارت‌به‌کارت)

7. مودال پرداخت → تب کارت‌به‌کارت → یک کد پیگیری وارد کن و ثبت کن.
8. **بررسی کن**: وضعیت پرونده هنوز `PAYMENT_PENDING` مونده (چون پرداخت فقط PENDING ثبت شده، نه SUCCESS).
9. با حساب EXPERT وارد شو → تب «تنظیمات پرداخت» → این تراکنش را «تأیید» کن.
10. **بررسی کن**: وضعیت پرونده‌ی سارا خودکار به `PROFILE_PENDING` تغییر کرد.

## بخش ۴ — پروفایل و آزمون‌ها

11. با شماره‌ی سارا دوباره وارد شو → فرم پروفایل را کامل کن و ذخیره کن.
12. **بررسی کن**: وضعیت پرونده خودکار به `TEST_PENDING` تغییر کرد.
13. یکی از آزمون‌ها را شروع کن، چند سؤال جواب بده، **صفحه را رفرش کن** → بررسی کن پاسخ‌ها ذخیره مونده (autosave).
14. هر ۵ آزمون (NEO، ECR، PAM، FMS، LAS) را تا انتها کامل کن.
15. **بررسی کن**: بعد از آخرین آزمون، وضعیت پرونده خودکار به `EXPERT_REVIEW` تغییر کرد.

## بخش ۵ — تکرار برای مراجع دوم («علی»، آقا)

16. بخش‌های ۱ تا ۴ را دقیقاً برای یک مراجع **مرد** با شماره‌ی دوم تکرار کن.

## بخش ۶ — کارشناس: یادداشت و تطبیق

17. با حساب EXPERT، به هر دو پرونده (سارا و علی) یک یادداشت INTERNAL و یک یادداشت SHAREABLE اضافه کن.
18. تب «میز تطبیق» → «تولید کاندیدهای جدید» را بزن.
19. **بررسی کن**: یک کاندید تطبیق بین سارا و علی ساخته شد.
20. **تست حیاتی جنسیت**: یک مراجع سوم هم‌جنس با سارا (مثلاً خانم) بساز و کل مسیر بخش ۱-۴ رو براش انجام بده، بعد دوباره «تولید کاندیدهای جدید» بزن → **بررسی کن**: هیچ کاندیدی بین سارا و این نفر سوم ساخته نشد (فیلتر جنسیت باید در سطح دیتابیس/منطق کار کنه).
21. کاندید سارا+علی را تأیید (Approve) کن.
22. **بررسی کن**: یک Introduction ساخته شد و وضعیت هر دو پرونده به `INTRODUCED` تغییر کرد.

## بخش ۷ — آشنایی و پیام‌رسانی

23. با شماره‌ی سارا وارد شو → تب «آشنایی‌ها» → پیش‌نمایش ناشناس علی را ببین (باید فقط اطلاعات عمومی/ناشناس باشه، نه اطلاعات خام پروفایل).
24. یک پیام برای علی بفرست.
25. با شماره‌ی علی وارد شو → **بررسی کن**: پیام سارا رو می‌بینه، و پیام‌رسانی دوطرفه کار می‌کنه.
26. هر دو طرف درخواست «تبادل اطلاعات تماس» بدن → **بررسی کن**: فقط وقتی هر دو درخواست دادن، تاییدیه‌ی نهایی ثبت می‌شه.

## بخش ۸ — نوبت‌دهی و تداخل زمانی

27. با شماره‌ی سارا، یک نوبت مشاوره برای یک روز/ساعت مشخص رزرو کن.
28. **بررسی کن**: تاریخ ثبت‌شده دقیقاً همون روزیه که از دراپ‌داون انتخاب کردی (نه تاریخ ثابت).
29. با شماره‌ی علی، **همون** روز و ساعت رو رزرو کن.
30. **بررسی کن**: پیام خطای «این بازه قبلاً رزرو شده» نمایش داده می‌شه و رزرو دوم ثبت نشد.

## بخش ۹ — چک‌های امنیتی (RLS)

این بخش رو از طریق Supabase Dashboard → SQL Editor یا یک ابزار API مثل curl/Postman با کلید anon (نه service role) امتحان کن:

31. با نشست ورودیِ سارا، تلاش کن مستقیماً یک ردیف `payments` با `status = 'SUCCESS'` insert کنی → **بررسی کن**: رد می‌شه (RLS).
32. با نشست سارا، تلاش کن پرونده‌ی علی (`cases` با `user_id` علی) رو SELECT کنی → **بررسی کن**: چیزی برنمی‌گرده.
33. با نشست سارا، تلاش کن نقش خودش رو به `ADMIN` تغییر بده (`update users set role='ADMIN' where id = auth.uid()`) → **بررسی کن**: تغییری اعمال نشد (تریگر `guard_role_change`).

## بخش ۱۰ — پرداخت زرین‌پال (در صورت فعال بودن)

34. در تنظیمات ادمین، زرین‌پال رو فعال کن (Merchant ID واقعی یا Sandbox).
35. یک پرداخت زرین‌پالی کامل انجام بده و به اپ بازگرد (Callback).
36. **بررسی کن**: در جدول `payments`، یک ردیف با `gateway='ZarinPal'` و `status='SUCCESS'` ثبت شده — و این ردیف باید توسط Worker (سرویس‌رول) نوشته شده باشه، نه مستقیم از کلاینت.
37. **بررسی کن**: وضعیت پرونده خودکار به `PROFILE_PENDING` رفت.

## بخش ۱۱ — گزارش‌گیری ادمین

38. با حساب EXPERT/ADMIN، تب «گزارش تخلفات/رخدادها» (Audit Log) را باز کن.
39. **بررسی کن**: اقدامات مهم (ساخت پرونده، تکمیل آزمون، تأیید تطبیق، ...) همه ثبت شده‌اند.

---

## اگر جایی این سناریو شکست خورد

هر شماره از این چک‌لیست رو که رد نشد، دقیقاً با همون شماره برام بفرست — می‌تونم مستقیم برم سراغ همون بخش از کد.

## بخش ۱۲ — ویژگی‌های جدید (بعد از بهبود کلی سیستم)

40. با نقش EXPERT، تب «داشبورد موفقیت» را باز کن → **بررسی کن**: قیف پرونده‌ها و درآمد نمایش داده می‌شود.
41. تب «مدیریت مجله آموزشی» → یک مقاله بنویس و منتشرش کن → **بررسی کن**: بدون ورود به سیستم (حالت ناشناس/Incognito) هم قابل مشاهده‌ست.
42. تب «مدیریت جلسات گروهی» → یک کارگاه با ظرفیت ۲ نفر بساز.
43. با شماره‌ی سارا و علی هرکدوم در آن ثبت‌نام کنید → **بررسی کن**: نفر سوم دیگر نمی‌تواند ثبت‌نام کند (ظرفیت تکمیل).
44. در تب «آشنایی‌ها»، برای معرفی سارا/علی یک «درخواست تماس تصویری» بزن → با کاربر دیگر «پذیرش» کن → **بررسی کن**: لینک Jitsi باز می‌شود و شماره تلفن هیچ‌جا نمایش داده نمی‌شود.
45. با نقش EXPERT، برای همان معرفی یک «جلسه معارفه خانوادگی» پیشنهاد بده → با هر دو کاربر «تایید حضور» کن.
46. هر دو طرف فرم «بازخورد بعد از آشنایی» را پر و ثبت کنند → **بررسی کن**: در «داشبورد موفقیت»، این معرفی در آمار «تمایل دوطرفه به ادامه» و بازخوردهای مثبت دیده می‌شود.
